A penetration test of a deliberately vulnerable Ubuntu machine and the web application running on it, written up as a report during my internship.

0x01 · objective

Objective

Examine the machine and its web application, collect the flags hidden on it, and report every weakness I could confirm.

Scope: one lab virtual machine, tested from a Kali VM on the same network.
0x02 · technologies

Tools

  • Kali Linux
  • Nmap
  • curl
  • grep
  • JWT decoding
  • Source review
0x03 · approach

Approach

  1. Opened GRUB recovery mode, which was not password protected, and reset the root password to get local access.
  2. Searched the file system for flags from that access.
  3. Scanned the machine with Nmap from Kali to see what it exposed.
  4. Tested the web application's login and signup forms by hand with curl.
  5. Read the application source to explain what I saw and to find the next step.
Physical or console access without a bootloader password is already root.
0x04 · findings

Findings

  1. Privilege escalation through mass assignment critical
    The signup endpoint trusted the role sent by the client, so a normal registration could create an admin. Reading the source showed a third role above admin, and the same flaw reached that page too.
  2. SQL injection in the signup form high
    An injected condition made the application report an unregistered username as taken, which showed the input was running as SQL.
  3. Hard-coded database password medium
    The database root password was stored in plain text in the application's configuration file.
0x05 · results

Results

Seven flags found, and access to the highest-privileged page in the application. Flags, passwords and request payloads are left out of this page on purpose.
