A lightweight tool for network vulnerability and cryptographic configuration reporting in small organisations. The goal is a report a small team can act on, ordered by what attackers actually exploit.

notice

This project is in progress. The problem is formulated and the method is designed. Implementation and evaluation are under way, so there are no results on this page yet.

0x01 · problem

Problem

Exploiting known vulnerabilities is now one of the most common ways attackers get in, and organisations struggle to patch even the critical ones that are known to be exploited. Full scanners such as OpenVAS are hard to configure. Lighter open-source tools each cover part of the job: some match services to CVEs but don't check cryptography, others audit TLS and SSH but don't match CVEs.

Most tools also rank findings by CVSS severity, which measures how damaging a flaw would be, not how likely it is to be exploited.

Scope: one IPv4 segment the organisation owns and is authorised to scan.
0x02 · objectives

Objectives

  1. Discover live hosts, open ports and service versions on a target network.
  2. Match services to known CVEs through the NIST National Vulnerability Database.
  3. Check TLS and SSH for deprecated protocols, weak ciphers, weak key exchange and bad certificates.
  4. Rank every finding and give a concrete fix for each one.
  5. Generate a readable report, and compare accuracy and speed with OpenVAS on the same lab.
0x03 · model

Ranking model

rf(λ) = λĉf + (1 − λ) ef

Each CVE finding gets a risk score that blends its normalised CVSS severity ĉ with its EPSS exploitation probability e. Setting λ = 1 reproduces the CVSS-only ranking current tools use. The ranking is judged by how high known-exploited (CISA KEV) findings appear, measured as average precision.

The whole design is framed as an optimisation over scan configuration and λ, under three hard limits: at most 10% false discoveries, no slower than OpenVAS, and no service disrupted during a scan.

Cryptographic findings have no CVSS or EPSS value, so their level comes directly from the rule they break (NIST SP 800-52 Rev. 2, IETF deprecations of TLS 1.0/1.1 and RC4).
0x04 · method

Method

  • Python
  • python-nmap
  • NVD API
  • EPSS
  • CISA KEV
  • TLS/SSH checks
  • HTML/PDF report
  • OpenVAS (baseline)
  1. Isolated host-only lab with intentionally vulnerable machines and one fully patched control host.
  2. Discovery and version detection with Nmap through python-nmap.
  3. CVE lookup against a frozen snapshot of NVD, EPSS and KEV data.
  4. Safe, non-intrusive checks for common misconfigurations and weak cryptography.
  5. Evaluation against OpenVAS: detection rate, false-discovery rate, ranking quality and scan time.
